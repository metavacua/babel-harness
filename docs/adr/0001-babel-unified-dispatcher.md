# ADR-0001 — `babel` unified dispatcher

**Status:** Proposed
**Supersedes:** none
**Depends on:** none
**Affects:** `bin/pi-harness`, `bin/coding-agent`, new `bin/babel`, `tests/test-babel.bash`, `lib/harness-common.sh`

---

## Context

Systematic-debugging (2026-07-06) of "babel is fragmented / confusing / wrong
fallback" found a single root cause, not a set of bugs: **there is no dispatch
layer.** `pi-harness` and `coding-agent` were each built bottom-up for a
different purpose and share nothing but two curl helpers in
`lib/harness-common.sh`. They diverge at every boundary:

| Boundary | `pi-harness` | `coding-agent` |
|---|---|---|
| Positional TASK | overwrite → **drops words** (`bin/pi-harness:201`) | accumulate (`bin/coding-agent:288`) |
| `--model` providers | `openrouter` / `ollama` | `larql` / else→`openrouter`; `ollama/…` silently misroutes |
| Default model | `auto` | `openrouter/free` |
| Fallback chain | OpenRouter → **Ollama** → repair | OpenRouter → **larql serve** |
| Output contract | JSONL | unstructured Goose text |
| Path handling | n/a | vindex **basename** passed to a tool needing an **absolute path** |
| Containment | cgroup **mandatory** | cgroup **best-effort** |

Reproduced bug (parser divergence): unquoted `write a hello function` yields
`[function]` under pi-harness and `[write a hello function]` under coding-agent.

Every listed symptom (fragmentation, parse errors, path confusion, UX traps,
wrong fallback) is a surface of the missing abstraction. Critically, the
**general** runner (pi-harness) falls back to **Ollama, which is currently
unusable on this host**, while the larql fallback we actually want already
exists — but only inside coding-agent.

## Decision

Introduce **`bin/babel`** as the sole entry point. It owns:

1. **Intake** — one quote-safe, accumulating arg contract; relative paths
   (vindex, task file refs) normalized to absolute at the door.
2. **Backend registry** — `pi`, `goose` (coding-agent), `larql`, and future
   frameworks (e.g. NCA) behind one `execute(task, opts) → {text, structured,
   exit}` contract. Existing binaries become executors.
3. **Selection** — task classification → backend (the RDL delegation table, but
   *inside babel*), with an explicit `--backend` override.
4. **One fallback chain** — OpenRouter → **larql smoll (containment-wrapped)** →
   error. **Ollama demoted to opt-in.**
5. **One output envelope** — a `{"type":"babel_result","backend":…}` JSONL line
   regardless of backend, ending the JSONL-vs-text parse split.
6. **One containment posture** — mandatory cgroup for every backend.

**Strategy (per the operator's "pursue all three"):** wrap+normalize, full
replace, and wrap+ADR are treated not as alternatives but as **candidate
implementations competing against one shared acceptance spec**,
`tests/test-babel.bash`. Candidates are generated by **self-application** —
babel run on its own codebase — and comparatively against an inline Claude
attempt. The acceptance suite, not operator or model judgment, is the arbiter;
this is fabrication-proof (a candidate cannot hallucinate past a red test).

The immediate path is wrap+normalize (dispatch to the existing tested
executors, fix the divergences at the babel layer, keep the 41 existing tests
valid), with the full replacement absorbed progressively under this ADR.

## Consequences

- Single command; the fallback the operator wants (cloud → larql smoll) becomes
  universal; the pi-harness word-drop bug is fixed at intake.
- `pi-harness` / `coding-agent` become internal executors first, then are
  progressively absorbed; Ollama is deprecated to opt-in.
- Added dispatch layer (new failure surface) — mitigated by `tests/test-babel.bash`
  as a standing contract and by keeping executors independently testable.
- "babel properly developed" becomes *measurable*: the pass-rate of a
  self-applied candidate against the acceptance suite is the metric.
